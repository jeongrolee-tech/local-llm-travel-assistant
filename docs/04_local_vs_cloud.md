# Local LLM vs Cloud API 비교

발제문 산출물 4번입니다.

| 항목 | 내용 |
|---|---|
| 로컬 | `qwen3.5:9b`, `gemma4:e4b` — 질문 10개 × **2회** = 모델당 20회 |
| Cloud | `gpt-4o-mini` — 공통 질문 5개 × **1회** = 5회 |
| 공통 질문 | Q1, Q2, Q3, Q7, Q9 ([questions.json](../data/questions.json) `cloud_subset`) |
| 입력 | 세 모델 모두 동일 — `system_prompt.txt` + `policy.md` + 질문 |
| 실험 일자 | 로컬 2026-09-17, Cloud 2026-09-17 |
| 원본 | [local_raw.jsonl](../results/local_raw.jsonl), [cloud_raw.jsonl](../results/cloud_raw.jsonl) |

> **반복 수가 다릅니다.** 로컬은 질문당 2회, Cloud는 1회입니다. 아래 비교는 **같은 5개 문항**으로 다시 집계한 값이며, 로컬의 좋은 결과 한 건만 골라 쓰지 않았습니다. Cloud는 n=5 이므로 로컬(n=10)보다 변동에 취약합니다.

## 1. 요약 비교표

| 기준 | Local LLM (`gemma4:e4b`) | Cloud API (`gpt-4o-mini`) | 판정 근거 |
|---|---|---|---|
| **Quality** | 91.7점 (n=10) | **92.9점** (n=5) | 실측 |
| **Latency** | **1.02초** (n=10) | 2.15초 / 첫 회 제외 1.48초 (n=5) | 실측, 네트워크 왕복 포함 |
| **Cost** | 장비 보유분 활용, 추가 과금 없음 | **$0.000196 / 호출** (추정) | 실측 토큰 × 공시 단가 |
| **Security** | **데이터가 장비 밖으로 나가지 않음** | 정책 문서와 고객 문의가 외부 API로 전송 | 운영 조건 분석 |
| **Infra / Ops** | GPU 장비 확보·관리, 모델 서빙 필요 | **인프라 운영 부담 없음** | 운영 조건 분석 |
| **Customization** | 모델 교체·양자화·내부망 구성 가능 | 제공 모델과 API 범위에 의존 | 운영 조건 분석 |

**Quality·Latency·Cost는 실측이고, Security·Infra·Customization은 운영 조건 분석입니다.** 뒤의 셋은 이번 실험에서 측정하지 않았습니다.

## 2. Quality — 실측

같은 5개 문항 기준으로 다시 집계했습니다.

| 모델 | 획득 / 만점 | 100점 환산 | n | 반복 |
|---|---|---|---|---|
| `gpt-4o-mini` (Cloud) | 39 / 42 | **92.9** | 5 | 1회 |
| `gemma4:e4b` (로컬 B) | 77 / 84 | **91.7** | 10 | 2회 |
| `qwen3.5:9b` (로컬 A) | 75 / 84 | 89.3 | 10 | 2회 |

**차이가 1.2점입니다.** 선정한 로컬 모델이 Cloud와 사실상 같은 수준입니다.

### 문항별

| 문항 | Cloud | `gemma4:e4b` | `qwen3.5:9b` | 비고 |
|---|---|---|---|---|
| Q1 (25일 전 취소) | 6 / 8 | 7, 7 / 8 | 6, 7 / 8 | Cloud가 `"25일 전까지"` 로 구간을 흐리게 표현 |
| Q2 (2인 취소 계산) | **8 / 8** | **8, 8 / 8** | 7, 6 / 8 | Cloud·로컬 B 모두 534,000원까지 완결 |
| Q3 (만 3세 요금) | **8 / 8** | 6, 7 / 8 | **8, 8 / 8** | 로컬 B만 712,000원 미계산 |
| Q7 (천재지변 면제) | 7 / 8 | 7, 7 / 8 | 7, 6 / 8 | 셋 다 근거 항목명 미제시 |
| Q9 (보험 한도) | **10 / 10** | **10, 10 / 10** | **10, 10 / 10** | 셋 다 지어내지 않음 |

### 항목별

| 항목 | Cloud | `gemma4:e4b` (전체 20회) | `qwen3.5:9b` (전체 20회) |
|---|---|---|---|
| 1. 정확성 | 1.80 | 1.90 | 1.80 |
| 2. 핵심 정보 누락 | 1.80 | 1.55 | 1.50 |
| 3. 지시·형식 준수 | 1.80 | 1.90 | 1.85 |
| **4. 한국어 표현** | **2.00** | 1.95 | 1.65 |
| 5. 정보 부족 시 대응 | 2.00 (1회) | 2.00 (4회) | 2.00 (4회) |

**Cloud는 한국어 표현에서 감점이 없었습니다.** 다만 n=5 라 로컬(n=20)과 같은 신뢰도로 볼 수 없습니다.

**P4는 Cloud에 적용하지 않습니다.** P4는 Q9·Q10 **4회** 기준의 로컬 필수 통과 조건인데, Cloud는 Q9만 1회 수행했습니다. Q10(범위 밖)은 공통 질문에 포함되지 않았습니다.

### Cloud의 감점 지점 (Q1)

> 출발 25일 **전까지** 취소하실 경우 수수료는 요금의 10%가 부과됩니다.

정책 문서상 30일 전 이전은 무료인데, `"25일 전까지"` 라는 표현은 그보다 이른 시점도 10%라는 오독을 유발합니다. 항목1에서 1점(인접 구간 혼동)입니다. 로컬 두 모델은 `'출발 29일 전 ~ 20일 전'` 구간을 명시했습니다.

## 3. Latency — 실측

| 모델 | 평균 응답 시간 | n | 비고 |
|---|---|---|---|
| `gemma4:e4b` | **1.02초** | 10 | 모델 적재 후 |
| `qwen3.5:9b` | 1.53초 | 10 | 모델 적재 후 |
| `gpt-4o-mini` | 2.15초 | 5 | **네트워크 왕복 포함** |
| `gpt-4o-mini` (첫 회 제외) | 1.48초 | 4 | 첫 호출 4.84초는 연결 수립 포함 |

**로컬이 더 빠릅니다.** 첫 회를 제외해도 `gemma4:e4b` 가 1.02초로 Cloud 1.48초보다 앞섭니다.

**비교 조건이 다릅니다.**

| 항목 | 로컬 | Cloud |
|---|---|---|
| 포함 구간 | 모델 추론만 (모델 적재 후) | 네트워크 왕복 + 서버 대기열 + 추론 |
| 첫 호출 비용 | 모델 로딩 3.9~5.1초 (워밍업으로 분리) | 연결 수립 포함 4.84초 |
| 변동 요인 | GPU 상태, 출력 길이 | 위 + 네트워크 상태, 서버 부하 |

로컬의 모델 로딩은 워밍업 1회로 분리했고, Cloud의 첫 호출 지연은 분리하지 않았습니다. **첫 회 포함/제외 양쪽을 모두 제시했습니다.**

## 4. Cost

### Cloud — 실측 토큰 기반 추정

| 항목 | 값 |
|---|---|
| 실행 | 5회 |
| 입력 토큰 합계 | 5,277 |
| 출력 토큰 합계 | 317 |
| 공시 단가 | 입력 $0.15 / 출력 $0.60 (per 1M, 2026-09-16 조사) |
| **추정 비용 (5회)** | **$0.000981** |
| **호출당 추정 비용** | **$0.000196** |

> **이것은 추정 비용이며 실제 청구 내역이 아닙니다.** 공시 단가에 실측 토큰 수를 곱한 값입니다. 실제 사용 내역은 [platform.openai.com/usage](https://platform.openai.com/usage) 에서 확인해야 합니다.

### 운영 규모 환산 — 가정에 기반한 추정

가정: 호출당 입력 ~1,055 토큰 / 출력 ~63 토큰 (실측 평균), 영업일 20일/월.

| 일 처리량 | 월 추정 비용 | 연 추정 비용 |
|---|---|---|
| 100건 | $0.39 | $4.7 |
| 500건 | $1.96 | $23.5 |
| 1,000건 | $3.92 | $47.1 |

**이 Use Case 규모에서 Cloud 토큰 비용은 사실상 무시할 수 있습니다.** 비용이 로컬을 선택할 근거가 되지 못합니다.

### Local — 정량화하지 않음

| 항목 | 상태 |
|---|---|
| 장비 | 수업용 노트북 1대 (기보유). 추가 구매 없음 |
| 전력 | **측정하지 않음** |
| 관리 공수 | **측정하지 않음** |
| 추가 과금 | 없음 |

**로컬 비용을 Cloud와 같은 단위로 비교할 수 없습니다.** 장비를 이미 보유해 한계비용이 0에 가깝지만, 전력과 관리 공수를 측정하지 않았으므로 "로컬이 더 싸다" 고 단정하지 않습니다.

## 5. Security — 운영 조건 분석

| 항목 | Local | Cloud |
|---|---|---|
| 정책 문서 전송 | 장비 밖으로 나가지 않음 | 매 호출마다 외부 API로 전송 |
| 고객 문의 전송 | 장비 밖으로 나가지 않음 | 매 호출마다 외부 API로 전송 |
| 데이터 보관 | 로컬 파일만 | 제공자 정책에 의존 |
| 통제 범위 | 전면 통제 가능 | 약관과 설정에 의존 |

**본 Use Case의 중요 가치 2순위가 데이터 보안입니다.** 실제 고객 문의와 사내 정책 문서를 다루므로 이 항목은 가중치가 높습니다.

> 본 실험은 **가상 문서와 가상 질문만** 사용했습니다. 실제 고객 데이터는 사용하지 않았습니다.

이 항목은 이번 실험에서 측정하지 않았습니다. 전송 여부라는 구조적 차이를 기술한 것입니다.

## 6. Infra / Operations — 운영 조건 분석

| 항목 | Local | Cloud |
|---|---|---|
| 초기 구성 | GPU 장비 확보, Ollama 설치, 모델 다운로드 (9.6 GB) | API 키 발급 |
| 상시 운영 | 모델 서빙 프로세스 유지, VRAM 관리 | 없음 |
| 장애 지점 | GPU 메모리 부족, 모델 적재 실패 | 네트워크, API 한도, 서비스 장애 |
| 확장 | 장비 추가 필요 | 호출 수만 늘리면 됨 |
| 버전 관리 | 태그·digest 로 고정 가능 | 제공자가 모델을 갱신할 수 있음 |

본 실험에서 확인한 로컬 운영 부담의 실례입니다.

| 사례 | 내용 | 상세 |
|---|---|---|
| VRAM 한계 | `num_ctx=8192` 에서 CPU 분할, 생성 속도 11% 하락 | README 9절 #8 |
| 동시 적재 불가 | VRAM 여유가 있어도 두 모델을 함께 올릴 수 없음 | README 8-1 |
| 모델별 기본값 차이 | Qwen3.5 는 thinking 기본 활성이라 빈 응답 발생 | README 9절 #6 |

**Cloud는 이 세 가지를 모두 겪지 않습니다.** 반면 모델 버전을 우리가 고정할 수 없습니다 — 로컬은 `digest` 로 고정했지만, Cloud 응답의 `model_returned` 값은 제공자가 바꿀 수 있습니다.

## 7. Customization — 운영 조건 분석

| 항목 | Local | Cloud |
|---|---|---|
| 모델 교체 | 자유 (후보 6개를 실제로 교체하며 비교) | 제공 모델 범위 내 |
| 양자화 선택 | 가능 (Q4_K_M 사용) | 불가 |
| 생성 설정 | `num_ctx`, `think`, `num_predict` 등 직접 제어 | API가 노출하는 범위 내 |
| 내부망 구성 | 가능 | 외부 연결 필수 |
| 파인튜닝 | 가능 (본 실험 범위 밖) | 제공자 지원 범위 내 |

본 실험 자체가 로컬 커스터마이징의 실례입니다. Kanana 커뮤니티 변환본을 직접 재빌드해 검증한 것(README 2-8)은 Cloud에서 불가능합니다.

## 8. 종합

| 기준 | 우세 | 근거 |
|---|---|---|
| Quality | **Cloud (근소)** | 92.9 vs 91.7 — 1.2점 차 |
| Latency | **Local** | 1.02초 vs 1.48~2.15초 |
| Cost | **판정 보류** | Cloud 토큰 비용은 무시 가능 수준. 로컬 전력·관리 비용 미측정 |
| Security | **Local** | 데이터가 장비 밖으로 나가지 않음 |
| Infra / Ops | **Cloud** | 운영 부담 없음 |
| Customization | **Local** | 모델·양자화·설정 전면 제어 |

**Cloud가 품질에서 앞섰지만 차이가 1.2점입니다.** 중요 가치 순위(한국어 표현 > 데이터 보안 > 응답 속도)를 적용하면, 품질이 사실상 동등한 상태에서 보안과 속도가 로컬 쪽입니다.

**단, Cloud 결과와 로컬 선정 이유는 분리해 기술합니다.** Cloud가 더 높은 점수를 받았다는 사실은 그대로 기록하며, 로컬을 선택한 근거는 품질 우위가 아니라 **동등한 품질에서의 보안·속도 이점**입니다. 운영 방식 권고는 [05_selection_report.md](05_selection_report.md)에 있습니다.

## 9. Cloud 모델 선택의 대표성

**`gpt-4o-mini` 는 저가 티어이며 Cloud 전체를 대표하지 않습니다.** 지식 컷오프 2023-10, 추론 토큰 없음, 입력 $0.15 / 출력 $0.60 per 1M 입니다. 플래그십 모델을 썼다면 점수가 더 높았을 것입니다.

이 모델을 고른 것은 의도한 선택입니다 (README 2-5).

| 이유 | 내용 |
|---|---|
| 비용 현실성 | 상담 봇에 실제로 붙일 수 있는 단가 |
| 격차의 적정성 | 로컬과 붙였을 때 "그래도 로컬을 쓸 이유가 있나" 를 따질 수 있는 수준 |
| 측정 안정성 | 추론 토큰이 없어 출력 길이와 응답 시간 측정이 깨끗함 |

### 다만 이 과제의 상한이 낮습니다

남은 점수(헤드룸)가 어디서 깎였는지 보면, 플래그십으로 올릴 수 있는 폭이 좁습니다.

| 모델 | 점수 | 헤드룸 | 감점 항목 |
|---|---|---|---|
| `gpt-4o-mini` | 92.9 | **7.1점** | 항목1 −1, 항목2 −1, 항목3 −1 |
| `gemma4:e4b` | 91.7 | 8.3점 | 항목2 −4, 항목3 −2, 항목4 −1 |
| `qwen3.5:9b` | 89.3 | 10.7점 | 항목2 −4, 항목3 −3, 항목4 −2 |

**Cloud가 잃은 3점은 전부 다른 문항의 다른 항목입니다** — Q1의 구간 표현(항목1), Q1의 금액 미제시(항목2), Q7의 근거 항목명 미제시(항목3). 추론 실패나 환각이 아닙니다.

**세 모델의 남은 감점이 항목2(핵심 정보 누락)와 항목3(지시·형식 준수)에 몰려 있습니다.** 금액을 계산해 제시하지 않거나 근거 항목명을 밝히지 않은 것으로, **모델 능력보다 지시문 설계에 가까운 문제**입니다. 출력 형식 요구를 지시문에 넣으면 세 모델 모두 개선될 여지가 있습니다 (README 8-2).

### 따라서 결론의 적용 범위

| 말할 수 있는 것 | 말할 수 없는 것 |
|---|---|
| 이 Use Case·이 평가셋에서 로컬 선정 모델이 **저가 Cloud 티어와 동등한 수준** | Cloud 일반, 또는 플래그십과 비교해 동등하다 |
| 문서 기반 단답 과제에서는 상한이 낮아 모델 격차가 덜 드러남 | 복잡한 추론 과제에서도 격차가 작다 |
| 이 규모에서 Cloud 토큰 비용은 무시할 수 있음 | 대규모 트래픽에서도 무시할 수 있다 |

**플래그십 비교는 수행하지 않았습니다.** 필요하다면 같은 5개 문항에 상위 모델을 1회씩 적용해 헤드룸이 실제로 메워지는지 확인하는 것이 다음 단계입니다.

## 10. 한계

| 한계 | 내용 |
