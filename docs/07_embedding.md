# 선택 실습 B — Embedding 실험

> 발제문 5절 「선택 실습 B. Embedding 실험」. **선택 실습은 필수 항목이 아닙니다.**
> 최종 모델 선정 근거에는 포함하지 않았습니다.

발제문이 요구한 흐름입니다.

> Sentence → Embedding Vector → Cosine Similarity → Semantic Similarity

| 발제문 요구 | 이 문서에서 |
|---|---|
| Sentence Transformers 로 위 흐름을 실습 | 2 ~ 5절 |
| 지정 3문장 비교 | 5절 |
| **생성 모델의 토큰 ID와 문장 비교용 임베딩을 구분** | 6절 |
| 같은 임베딩 모델·설정으로 비교 | 1절 — 전 단계 동일 모델 고정 |
| **유사도 값을 답변의 사실성 점수로 해석하지 않음** | 7절 — 실측으로 확인 |
| Vector DB·RAG 시스템 구현은 요구하지 않음 | 구현하지 않음. 8절은 원리 확인까지만 |

## 1. 실험 환경

| 항목 | 값 |
|---|---|
| 라이브러리 | `sentence-transformers` 6.1.0 |
| 임베딩 모델 | **`jhgan/ko-sroberta-multitask`** (약 442 MB) |
| 벡터 차원 | **768** |
| 최대 입력 | **128 토큰** |
| 실행 장치 | **CPU** (`torch 2.14.0+cpu`, CUDA 미사용) |

**모든 단계에서 같은 모델·같은 설정을 썼습니다.** 발제문의 "같은 임베딩 모델·설정으로 비교" 요구에 따른 것입니다.

CPU 실행은 의도한 결과는 아니지만 유리하게 작용했습니다. Ollama 가 VRAM 3,077 MiB 를 점유한 상태에서 torch 까지 GPU 를 잡으면 충돌하는데, 두 시스템이 분리되어 서로 간섭하지 않았습니다.

### 왜 생성 모델이 아니라 별도 모델인가

| | 생성 모델 (`gemma4:e4b`) | 임베딩 모델 |
|---|---|---|
| 출력 | 다음에 올 토큰 | **벡터 1개** |
| 용도 | 답변 작성 | 비교·검색 |
| 크기 | 8.0B | 약 0.1B |

생성 모델 내부에도 토큰별 임베딩이 있지만 **토큰 단위이고 문장 비교용으로 학습된 것이 아닙니다.** 발제문이 문장 비교에 Sentence Transformers 를 지정한 이유입니다.

## 2. Sentence → Embedding Vector

| 문장 | 글자 수 | 벡터 크기 |
|---|---|---|
| 고양이 | 3 | **(768,)** |
| 고양이가 소파 위에 있다 | 13 | **(768,)** |
| 제공된 자료에 따르면 출발 25일 전 취소 시… | 86 | **(768,)** |

**글자 수와 무관하게 항상 768개입니다.** 문장을 의미 공간의 좌표 한 점으로 바꾸기 때문이며, 축의 개수가 768 로 고정된 것입니다.

벡터 안의 값은 사람이 해석하는 숫자가 아닙니다.

| 항목 | 값 |
|---|---|
| 앞 6개 | `-0.5975, -0.3624, +0.7449, +1.1513, -0.3481, +0.6744` |
| 범위 | −1.6441 ~ +1.3679 |
| 평균 | **−0.0317** |

평균이 0 근처이고 양옆으로 퍼져 있습니다. 값 자체가 아니라 **두 벡터의 방향이 얼마나 가까운가**만 사용합니다.

### 128 토큰 한계

| | 토큰 |
|---|---|
| 이 모델의 한계 | **128** |
| `data/policy.md` 전문 | **873** |

**정책 문서를 통째로 임베딩할 수 없습니다.** RAG 가 문서를 조각내는(chunking) 이유가 검색 때문만이 아니라 여기에도 있습니다. 실제로 8절에서 이 한계가 실패를 만들어냈습니다.

## 3. Cosine Similarity — 직접 계산

```
cos(A, B) = (A · B) / (|A| × |B|)
```

두 문장으로 손계산했습니다.

- A = "고양이가 소파 위에 있다"
- B = "소파 위에 고양이가 앉아 있다"

| 항목 | 값 |
|---|---|
| A · B (내적) | +133.8312 |
| \|A\| | 12.0309 |
| \|B\| | 11.9355 |
| **cos = 133.8312 / (12.0309 × 11.9355)** | **+0.932003** |
| `util.cos_sim` (라이브러리) | **+0.932003** |
| 차이 | 7.28e-08 (부동소수점 오차) |

**라이브러리가 하는 계산이 이 세 줄뿐임을 확인했습니다.**

### 왜 거리가 아니라 각도인가

B 를 2배로 늘려(`B2 = B * 2`) 방향은 그대로 두고 길이만 바꿨습니다.

| | A vs B | A vs B2 |
|---|---|---|
| 유클리드 거리 | 4.4201 | **13.3882** |
| **코사인 유사도** | 0.932003 | **0.932003** |

**거리는 3배 변했지만 코사인은 그대로입니다.** 문장이 길거나 표현이 강해 벡터가 커져도 의미가 같으면 같게 나와야 하므로, 길이를 무시하는 이 성질이 필요합니다.

### 정규화

크기를 1 로 맞추면 분모가 1 이 되어 **내적 자체가 코사인**이 됩니다.

| | 값 |
|---|---|
| 정규화 후 \|A\|, \|B\| | 1.000000 |
| 정규화한 두 벡터의 내적 | **+0.932003** |

벡터 DB 가 저장 시점에 정규화해 두는 이유입니다 — 검색할 때마다 나눗셈을 반복하지 않고 내적만 하면 됩니다.

## 4. Semantic Similarity — 발제문 지정 3문장

| 비교 | 유사도 | 판정 |
|---|---|---|
| S1 "고양이가 소파 위에 있다" vs S2 "소파 위에 고양이가 앉아 있다" | **+0.9320** | 의미 가까움 |
| S1 vs S3 "오늘 주식시장이 상승했다" | **−0.0194** | 무관 |
| S2 vs S3 | **−0.0349** | 무관 |

**S1·S2 는 어순도 서술어도 다른데 0.93 입니다**("있다" vs "앉아 있다"). 글자가 아니라 의미를 봅니다. 주제가 다른 S3 는 0 근처로 떨어집니다.

여기까지가 발제문 요구사항입니다.

## 5. 확장 — 임베딩은 단어 겹침과 무엇이 다른가

요구사항만으로는 임베딩이 무엇을 보는지 드러나지 않아 두 문장을 추가했습니다.

| # | 문장 | 노린 것 |
|---|---|---|
| S4 | 소파가 고양이 위에 있다 | 단어는 거의 같고 **의미가 뒤집힘** |
| S5 | 야옹이가 쿠션에 누워 있다 | 단어는 안 겹치고 **의미가 비슷** |

비교 기준으로 어휘 겹침(Jaccard)을 함께 계산했습니다. 키워드 매칭이 보는 값과 같은 성격입니다.

| 기준 S1 과 비교 | 어휘 겹침 | **임베딩** | 성격 |
|---|---|---|---|
| S2 소파 위에 고양이가 앉아 있다 | 0.800 | **+0.9320** | 어순·서술어 다름 |
| S3 오늘 주식시장이 상승했다 | 0.000 | **−0.0194** | 주제 다름 |
| **S4 소파가 고양이 위에 있다** | 0.333 | **+0.9546** | **의미 반대** |
| S5 야옹이가 쿠션에 누워 있다 | 0.143 | **+0.3881** | 단어 다름, 의미 비슷 |

### 관찰 1 — 동의어 관계를 약하게 잡습니다

S5 는 "고양이/야옹이", "소파/쿠션" 처럼 겹치는 단어가 거의 없는데도(어휘 겹침 0.143) 임베딩은 0.3881 입니다. 무관한 S3(−0.0194)보다 확실히 높으므로 **동의어 관계를 잡아내기는 합니다.**

다만 0.3881 은 높은 값이 아닙니다. **"찾아낸다" 가 아니라 "약하게 잡는다" 가 정확한 서술입니다.**

### 관찰 2 — 뒤집힌 의미를 구분하지 못합니다

**S4 가 1위입니다(+0.9546). 올바른 패러프레이즈인 S2(+0.9320)보다 높습니다.**

| 의미대로라면 | 실제 순위 |
|---|---|
| S2 (같은 의미) 1위 | 2위 |
| S5 (비슷한 의미) 2위 | 3위 |
| **S4 (뒤집힌 의미) 3위** | **1위** |
| S3 (무관) 4위 | 4위 |

"소파가 고양이 위에 있다" 는 물리적으로 성립하지 않는 문장입니다. 그런데도 최고점을 받았습니다.

**임베딩은 "고양이·소파·위에·있다" 라는 재료가 같으면 가깝다고 봅니다. 그 재료가 어떻게 조립되었는지는 약하게 봅니다.** 이 성질이 7절의 핵심입니다.

## 6. 토큰 ID와 임베딩의 구분

**발제문이 명시적으로 요구한 항목입니다.** 둘 다 "문장을 숫자로 바꾼 것" 이라 혼동하기 쉽습니다.

문장 `"고양이가 소파 위에 있다"` 를 두 방식으로 바꾼 결과입니다.

| | 토큰 ID | 임베딩 |
|---|---|---|
| 결과 | `[0, 7003, 2116, 11559, 1485, 2170, 1513, 2062, 2]` | `-0.5975, -0.3624, +0.7449, …` |
| 자료형 | 정수 | 실수 |
| 개수 | **9개** — 문장 길이에 비례 | **768개** — 항상 고정 |
| 뜻 | 사전의 몇 번째 칸 | 의미 공간의 좌표 |
| 크기 비교 | **의미 없음** | 방향에 의미 있음 |
| 만드는 주체 | 토크나이저 | 모델 전체 |

토큰 조각은 다음과 같습니다.

```
['[CLS]', '고양이', '##가', '소파', '위', '##에', '있', '##다', '[SEP]']
```

`##` 는 앞 단어에 이어 붙는 조각이라는 표시입니다. **조사가 분리되어 있습니다** — 한국어는 조사가 붙었다 떨어졌다 하므로 이렇게 쪼개야 사전이 작아집니다(서브워드 토크나이제이션). `[CLS]`·`[SEP]` 는 문장 시작·끝 표식이며, 9개 중 2개가 특수 토큰입니다.

### 인접한 토큰 ID 는 아무 관계가 없습니다

| ID | 토큰 |
|---|---|
| 7001 | 극단 |
| 7002 | 급격 |
| **7003** | **고양이** |
| 7004 | 빌려 |
| 7005 | 그나 |

**ID 가 1 차이 나도 뜻은 전혀 무관합니다.** 사전에 나란히 적혔을 뿐입니다.

| | 가까운 숫자끼리 비슷한가 |
|---|---|
| 토큰 ID | **아니오** |
| 임베딩 | **예** (4절에서 확인) |

따라서 **토큰 ID 끼리 빼거나 평균 내는 연산은 의미가 없습니다.** 임베딩은 그 연산이 성립합니다.

### 모델이 다르면 토큰 수도 ID 도 다릅니다

본 실험에서 측정한 값입니다([02_model_comparison](02_model_comparison.md) 3절).

| 모델 | 같은 한국어 문서의 토큰 수 | Kanana 대비 |
|---|---|---|
| **Kanana 2 3B** (한국어 특화) | **811** | 기준 |
| Qwen3.5 | 980 | +20.8% |
| Gemma 4 | 1,072 | +32.1% |

**토큰이 적을수록 토크나이저 효율이 좋습니다.** 한국어 특화 모델이 가장 효율적이었습니다. 다만 그 효율이 답변 품질로 이어지지는 않았습니다 — Kanana 는 P4 에서 탈락했습니다.

### 어디에 무엇을 쓰는가

| | 쓰는 곳 |
|---|---|
| **토큰 ID** | 생성 모델에 입력을 넣을 때. 본 실험의 `prompt_tok`·`out_tok` 이 이 개수입니다 |
| **임베딩** | 문장끼리 비교·검색할 때. 답변을 만들지 않습니다 |

## 7. 유사도는 사실성 점수가 아닙니다

발제문이 경고한 항목을 **우리 프로젝트의 실제 업무 문장**으로 확인했습니다.

### 사례 1 — 비자 조항 (policy.md 8절)

> 기준: 일본은 대한민국 여권 소지자에 한해 **90일** 이내 관광 목적 체류 시 비자가 면제됩니다.

| 사실 | 유사도 | 문장 |
|---|---|---|
| ✅ 참 | **+0.8809** | 한국 여권이 있으면 관광 목적으로 일본에 90일까지 비자 없이 갈 수 있습니다 |
| ❌ **거짓** | **+0.8404** | …**30일** 이내 관광 목적 체류 시 비자가 면제됩니다 |
| ❌ 거짓 | +0.6961 | …관광 목적 체류 시 비자가 **필요합니다** |
| − 무관 | +0.1346 | 조식 3회가 요금에 포함되어 있습니다 |

참이 0.04 차이로 앞섰습니다. **그러나 명백한 거짓이 0.8404 입니다.** 문턱값을 0.8 로 두고 "사실과 일치한다" 고 판정하면 **거짓이 통과합니다.**

### 사례 2 — 취소 수수료 (policy.md 5절)

> 기준: 출발 29일 전부터 20일 전 사이에 취소하면 요금의 **10%** 가 부과됩니다.

| 사실 | 유사도 | 문장 |
|---|---|---|
| ❌ **거짓** | **+0.7748** | …요금의 **50%** 가 부과됩니다 |
| ✅ 참 | +0.7635 | 출발 25일 전에 취소하시면 요금의 10%를 내셔야 합니다 |
| ❌ 거짓 | +0.6237 | …수수료가 없습니다 |
| − 무관 | +0.1743 | 인천국제공항에서 출발하는 오사카 3박 4일 패키지입니다 |

**거짓이 참보다 높습니다.** 10% 를 50% 로 바꾼 문장이 올바른 패러프레이즈를 이겼습니다.

### 왜 이런가

숫자만 바뀐 문장은 **글자 두 자**가 달라졌을 뿐이고, 임베딩이 보는 "무엇에 대한 말인가" 는 그대로입니다. 5절에서 본 S4(뒤집힌 의미가 1위)와 같은 성질입니다.

### 본 실험과의 연결

Kanana 2 3B 는 문서에 없는 `"3천만원"`, `"90일 무비자"` 를 지어내 P4 에서 탈락했습니다(README 2-8).

**만약 유사도로 자동 채점했다면 그 답변들은 원문과 높은 유사도를 받아 통과했을 것입니다.** 지어낸 답도 원문과 같은 주제를 같은 말투로 말하기 때문입니다.

> **이 프로젝트가 [data/rubric.md](../data/rubric.md) 로 사람이 채점한 이유입니다.**
> 유사도는 "비슷한가" 를 재는 자이지 "맞는가" 를 재는 자가 아닙니다.

## 8. 검색 실습 — 예상과 다르게 실패했습니다

**Vector DB 와 RAG 시스템은 구현하지 않았습니다.** 발제문이 요구하지 않았습니다. 검색의 원리만 확인했습니다.

`policy.md` 를 절 단위 9개 조각으로 나누고, 질문과 가장 가까운 절을 찾게 했습니다.

| 질문 | 검색 1위 | 정답 | |
|---|---|---|---|
| Q1 출발 25일 전 취소 수수료 | 5. 취소 수수료 규정 | 5. 취소 수수료 규정 | ✅ |
| **Q5 혼자 가면 추가 요금** | **4. 불포함 사항** | 2. 요금 기준 | ❌ |
| **Q6 저녁 식사 포함 여부** | **2. 요금 기준** | 4. 불포함 사항 | ❌ |

**3문항 중 1개만 맞혔고, Q5 와 Q6 은 답이 서로 뒤바뀌었습니다.**

### 원인 진단

가설 세 가지를 확인했습니다.

#### H1 — 128 토큰 초과로 잘림 · **사실이나 이번 실패의 원인은 아님**

| 절 | 토큰 | 상태 |
|---|---|---|
| 5. 취소 수수료 규정 | **151** | **잘림** |
| 나머지 8개 | 22 ~ 111 | OK |

`transformers` 가 `151 > 128` 경고를 출력했습니다. **취소 수수료 표의 뒷부분이 임베딩에 반영되지 않았습니다.**

그런데 **Q1 은 성공했습니다.** Q1 이 물은 "25일 전" 이 표 앞쪽이라 살아남은 것입니다. **운이 좋았던 것이며, "6일 전" 을 물었다면 실패했을 가능성이 높습니다.** 이는 지금 드러나지 않은 잠재 결함입니다.

#### H2 — 조각이 너무 큼 · **기각**

| 분할 방식 | 조각 수 | 정답률 |
|---|---|---|
| 절 단위 | 9 | 1 / 3 |
| **문장 단위** | **23** | **1 / 3 (동일)** |

**잘게 쪼개도 전혀 나아지지 않았습니다.** 문제는 조각 크기가 아닙니다.

#### H3 — 질문의 핵심어가 틀 단어에 밀림 · **확인됨**

문장 단위 검색에서 Q6 이 고른 문장입니다.

> Q6 "**저녁 식사**는 **요금**에 **포함**되어 있나요?"
> → `2. 요금 기준: 성인(만 12세 이상): 890,000원`

**"저녁 식사" 가 아니라 "요금" 에 끌렸습니다.** 질문의 핵심어보다 틀에 해당하는 단어가 이겼습니다.

| 질문 | 1위와 정답의 점수 차 |
|---|---|
| Q5 | 0.0604 |
| **Q6** | **0.0149** |

Q6 은 0.015 차이로, 모델이 사실상 구분하지 못하고 있습니다. 5절에서 본 "의미가 뒤집혀도 구분 못 함" 과 같은 계열의 약점입니다.

#### H4 — 모델 용도 불일치 · **미검증**

`ko-sroberta-multitask` 는 **문장 대 문장 유사도(STS)** 로 학습된 모델입니다. 이번에 시킨 것은 **질문 → 문서 검색**이며 성격이 다릅니다.

| | 학습된 과제 | 이번에 시킨 것 |
|---|---|---|
| 입력 A | 평서문 | **의문문** |
| 입력 B | 평서문 | 문서 조각 |

검색 전용 모델(`bge-m3`, `multilingual-e5` 등)은 질문과 문서를 비대칭적으로 다루도록 학습됩니다. **이 가설은 검증하지 않았습니다.** 다른 모델을 쓰면 "같은 임베딩 모델·설정으로 비교" 조건이 깨지고, 발제문 범위를 넘습니다.

### 가장 실용적인 발견 — top-k

정답이 몇 위였는지 확인했습니다.

| 질문 | 정답 순위 | 1위 점수 | 정답 점수 |
|---|---|---|---|
| Q1 | **1위** | 0.6468 | 0.6468 |
| Q5 | **2위** | 0.4698 | 0.4094 |
| Q6 | **2위** | 0.3486 | 0.3337 |

**1위만 쓰면 1/3 이지만, 상위 2개를 쓰면 3/3 입니다.**

실제 RAG 가 조각을 1개만 가져오지 않고 **3~5개를 모아 생성 모델에 넘기는 이유**가 이것입니다. 검색이 완벽하다고 가정하지 않고, 정답이 상위권에 있기만 하면 되도록 설계합니다.

### 문턱값의 필요성

7절 실험에서 Q9("여행자보험 상해 보장 한도")를 넣었을 때, **문서에 보험 조항이 없는데도 검색은 `4. 불포함 사항` 을 0.4030 으로 골랐습니다.**

검색은 언제나 1등을 내놓습니다. **"없다" 고 말해주지 않습니다.** 실제 RAG 가 유사도 문턱값을 두고 일정 점수 미만이면 "관련 문서 없음" 으로 처리하는 이유입니다. 문턱값이 없으면 엉뚱한 조항을 근거랍시고 모델에 넘기게 됩니다.

## 9. 정리 — 어디에 쓰고 어디에 쓰지 않는가

| 용도 | 유사도로 | 근거 |
|---|---|---|
| 의미가 비슷한 문장 찾기 | **된다** | 4절 — 어순·서술어가 달라도 0.9320 |
| 무관한 문장 걸러내기 | **된다** | 4절 — 주제가 다르면 0 근처 |
| 어느 조항을 봐야 하는지 찾기 | **조건부** | 8절 — 1위만으로는 1/3, top-2 면 3/3 |
| 뒤집힌 의미 구분하기 | **안 된다** | 5절 — S4 가 1위 |
| **답변 내용이 맞는지 판정하기** | **안 된다** | 7절 — 거짓이 참보다 높음 |

**RAG 는 앞의 셋만 유사도에 맡기고, 답변이 맞는지는 생성 모델과 사람의 검수에 맡깁니다.** 본 실험이 루브릭으로 채점한 것과 같은 이유입니다.
